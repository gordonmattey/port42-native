## THE NEXT BIG WORK: API/tool-use unification (#2) — the keystone
Everything points here; it now has forcing functions. Evidence gathered live this session:
- **The JS bridge `call()` NEVER rejects** — a failed call resolves with `{error}`, so every port's
  `try/catch` is decoration. Only `ai.complete` hand-throws. (A voice port said LISTENING while the
  mic was refused.)
- **Every camelCase method is unreachable over the gateway** — `port.getHtml` → `port_getHtml` →
  Unknown tool; real name is `port.get_html`. Same for `audio.stopCapture`, `automation.runAppleScript`.
- **`ports.list` returns an ARRAY to port JS and a TEXT BLOB to agents** — the thesis in one method.
- **`port.manage` has two implementations** (PortBridge + ToolExecutor) — adding "background" needed
  it in both (hit live).
- **Permissions key on a LABEL, not a principal** — gateway's authenticated `peer.ID` is flattened to
  `remote-http-cal`; every gateway caller shares it. `PermissionRequester` is an accidental first
  draft of a principal.
- **The shape:** extract one base impl per method + a real **principal** carried end to end. The
  AI-edit feature ("through the port42 API", `AppState.invokeCompanion` shared base) and chrome-as-
  ports (capability-scoped ports) both require it. See the AI-edit and MCP items in the todo.

## The through-line worth remembering
Two themes ran through everything: **"the system knows; nothing exposes the knowing"** (versions,
reopen, presentation state all existed and had no UI) and **"the platform hides its failures"** (CDN
block, never-rejecting bridge, 50KB terminal.exec cap, invalid SF Symbol = invisible button, NSPopover
sizes-once). The ports skill should teach the platform to follow its own "make failure visible" rule.
