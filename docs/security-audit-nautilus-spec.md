# Security audit specification: the nautilus release

Written 2026-09-26. **This is the brief for an audit, not the audit.** It defines what must be
established, what is in scope, and how each property is to be tested. No finding in this document is
an audit result.

## Purpose

Nautilus rewrote the authentication path, deleted the messaging hub, removed the in-app model, added
a chat port, added agent teams, and is part way into a remote transport. The release is close. The
audit establishes whether the security properties the product claims are true of the code as it
stands, and what must be true before Phase 4 makes any of it reachable from another machine.

**Non-goals.** Not a code review, not a performance review, not a design critique. A finding is a
statement that a required property does not hold, with the evidence that shows it.

## Subject

Everything that changed between the last release and the release candidate, plus everything the
changes touch.

| Area | What landed |
|---|---|
| Phase 0 | The gateway hub deleted; one app connection (`GatewayDoor`); the credential stamped at `identify`; terminal creation gated; undeclared arguments refused |
| Phase 1 | In-app model engine removed; `AgentAuth` and the Keychain credential read removed; messaging, sync, tunnel and invite payloads removed; migration v47 drops hub columns; first run rebuilt on a CLI agent |
| Phase 2 | Placement replaces re-gridding; per-desktop positions (v46); close becomes archive |
| Phase 3 | The pipe: subscriptions waking rested subscribers; invisible ports; `terminal.exec` inside ports |
| `/imagine` | A command that creates a space, spawns a lead and engineers as visible agents, gives them role prompts, and enforces a version budget |
| Phase 4 | **On `nautilus-phase4`, substantially landed.** 4,369 insertions: a relay (`gateway/relay/`, deployed on Railway), a transport seam with chunking and peer ids, Noise IK, one Ed25519 key per instance, `port42://<peer>/<portId>`, remote grants per caller, invites with an optional code, waiting-room approval by name, and HMAC attestation from the gateway to the app. Audited as part of this release |

## Threat model

State it before testing, because a finding is only a finding relative to a model.

**Assets.** The user's files and shell; their provider credentials and sign-ins; the content of their
ports and chats; the machine's devices (screen, camera, microphone, clipboard); the integrity of what
a port displays.

**Actors, in ascending order of trust:**

1. **A remote stranger.** No credential, reaching the relay's public address. Phase 4 makes this
   actor real, and it is the reason for the audit's timing.
1a. **The relay operator, and anyone who compromises the relay.** Sees every session's traffic and
   controls its delivery. Third-party infrastructure, so it must be assumed hostile rather than
   trusted.
2. **An invited guest.** Holds a credential for one shared port, by intent.
3. **A port.** Untrusted JavaScript the user did not write, possibly generated by a model, running
   with `window.port42`.
4. **An enrolled client.** A CLI agent or script with a token, named but not trusted.
5. **A companion.** An enrolled client the user has adopted into a space.
6. **A process running as the user.** Can read any file the user can, including token files. Outside
   the model: the tree already states this limit.

**Trust boundaries.** Between a port's JS and the bridge. Between a client and the gateway. Between
the gateway and the app. Between one port and another. Between one space and another. Between this
machine and any remote peer.

## Requirements

Each is a property that must hold. The audit reports HOLDS, FAILS, or UNPROVEN with evidence. An
UNPROVEN is a result, not a gap in the audit, provided it says what would settle it.

**Authentication**

- **A1.** No path reaches a bridge method without a named caller.
- **A2.** A credential minted for one instance is refused by another.
- **A3.** A credential presented on one connection cannot be replaced per message. (Phase 0 stamps at
  `identify`; verify both `/call` and `/ws`.)
- **A4.** A revoked client stays revoked across an app restart and a terminal respawn.

**Authorization**

- **O1.** Every method that reads or writes another port's state requires a grant naming that port.
- **O2.** A port cannot read, write, close, execute in, or enumerate a port it was not granted.
- **O3.** A port cannot read a space it was not granted, including chat.
- **O4.** A grant given to one principal does not extend to ports that principal creates later.
- **O5.** Capability declarations (`port.setCapabilities`) are not used as an authorization input
  anywhere, or if they are, they are not self-asserted.

**Credentials and secrets**

- **C1.** The app holds no model provider credential and makes no provider request.
- **C2.** A child process receives only the environment it needs. Specifically, whether a spawned
  agent inherits provider credentials from the user's profile is a decision, not an accident.
- **C3.** Token files are `0600` in a `0700` directory, per instance, and are never logged, never
  placed in a URL, and never written into an instruction file.
- **C4.** Nothing deleted in Phase 1 left a secret behind: signing keys, Apple identity, encryption
  keys and provider accounts are gone from the database and the Keychain, not merely unreferenced.

**Isolation**

- **I1.** A port's JS cannot reach the host beyond the bridge surface.
- **I2.** `port.exec` executes with the caller's authority, not the target port's.
- **I3.** A port cannot cause another port to act on its behalf.
- **I4.** An agent spawned by `/imagine` is confined to the space it was created for.

**Remote**

- **R1.** A remote caller is authenticated as a peer id derived from a key it proves it holds, and
  grants key on that peer. A claimed peer id that does not match the handshake is refused.
- **R2.** A remote caller sees only the ports it was granted. It cannot enumerate ports, spaces or
  companions.
- **R3.** An invite grants one port and is not a general credential. Its code, where required, is
  rate-limited and single-use.
- **R4.** A guest credential cannot be replayed after use or after revocation.
- **R5.** No token crosses the network, and the relay cannot read or alter what it carries.
- **R6.** The relay is untrusted. Confidentiality and integrity survive a hostile relay that reorders,
  drops, duplicates, truncates or forges frames, and that lies about who is connected.
- **R7.** The gateway's HMAC attestation to the app cannot be forged by a remote peer, and its key is
  not derivable from anything a peer sees.
- **R8.** An instance's Ed25519 key is generated with a system RNG, stored where only the user can
  read it, and a compromised or rotated key revokes what it authorized.
- **R9.** Chunk reassembly is bounded and cannot be used to exhaust memory or to splice frames from
  different senders.
- **R10.** A debug affordance cannot be enabled in a release build, proven by build configuration
  rather than by convention.
- **R11.** The lock screen is not treated as access control anywhere. `lockApp()` sets
  `showDreamscape = true` and `unlock()` sets it to false, with no credential checked and no consumer
  of the state outside the UI; the gateway answers calls throughout. The requirement is that nothing
  depends on it for security, and that it is documented as presentation. Making it a real boundary is
  separate work, specified in `docs/research/os-authentication-lock.md`.

**Consent**

- **N1.** A permission prompt names the caller and what it is asking for.
- **N2.** A denial is distinguishable from an error, and from a timeout.
- **N3.** A prompt that cannot be shown does not silently become an allow, and does not hang without
  a resolution.
- **N4.** Revocation in Settings takes effect for in-flight and subsequent calls.

**Integrity and supply chain**

- **S1.** Every executable in the shipped bundle is Developer ID signed and notarized.
- **S2.** The update feed advertises what the artifact actually declares.
- **S3.** Generated instruction files carry no credential and no instance-specific secret.
- **S4.** A port's content cannot escalate by being restored from history.

**Resource and denial**

- **D1.** No bridge method can return unbounded data into a caller's context.
- **D2.** No caller can spawn unbounded processes, ports, companions or agents.
- **D3.** `/imagine`'s budget cannot be bypassed by the agents it creates.

## In scope

The Swift app, the Go gateway, the CLI, the shim, the generated instruction files, the database and
its migrations, the shipped bundle and its signing, the guest page, and the `/imagine` command and
the agents it creates.

## Out of scope

A process already running as the user. macOS platform vulnerabilities. The security of the model
providers the CLIs authenticate with. Physical access. Phase 4 code that has not landed, which is
reported as "not present" rather than tested.

## Known findings: verify, do not rediscover

`docs/research/security-bridge-authorization.md` and `docs/research/defects-found.md` already record
these. The audit confirms each is still true, records if fixed, and rates severity against the threat
model above. Time spent rediscovering them is time not spent looking elsewhere.

1. 41 of 69 registry methods ungated; the dispatcher hardcodes the object as `.machine`.
2. `port.push` types into any live terminal; `port.subscribe` streams any terminal's output;
   `ports.list` enumerates every port in every space. All ungated.
3. `port.exec` runs under the victim's principal.
4. `PortBridge.init` unions the creator's port 0 grants into a new port as a pregrant.
5. Revoking a `child` client is undone by the next launch (`upsertClient` clears `revokedAt`).
6. The guest page carries a full client token in a query string.
7. No cap on tool results on the live path; `port.console` can return 400,000 characters.
8. A child process inherits the parent's environment; `claude` authenticates from an inherited
   `ANTHROPIC_API_KEY`.
9. The shipped `port42` CLI is not Developer ID signed (`build.sh:383` versus `:326`).
10. `LOCAL_PEERCRED` on a TCP socket fails open and reports uid 0.
11. Identity is keyed on mutable display names; companions and grantees both inflate without bound.

## Test scenarios

Each is: setup, action, expected, and what settles it if the expectation is ambiguous. Run on a
dedicated dev instance with its own data directory. Never against the daily driver, and never against
an instance another session is using.

**T1. Anonymous reach.** With no credential, call `/call` and `/ws` for: `ports.list`,
`port.getHtml`, `space.list`, `chat.read`, `port.push`, `terminal.exec`. Expect refusal on every one.
Covers A1.

**T2. Cross-instance credential.** Present a Dev3 token to Dev2 and the reverse. Expect refusal.
Covers A2.

**T3. Per-envelope credential swap.** Over `/ws`, identify as client X, then send a call whose
envelope names client Y. Expect the call attributed to X. Covers A3.

**T4. Revocation durability.** Revoke a spawned terminal's client in Settings. Restart the app.
Re-read `clients.revokedAt` and retry a gated call. Expect it stays revoked. Covers A4, finding 5.

**T5. Port-to-port reach.** Create two ports, A and B, with different creators and no grants between
them. From A, attempt each of: read B's HTML, read B's DOM, exec in B, push to B, update B, close B,
list all ports, read another space's chat. Record which succeed. Covers O1, O2, O3, findings 1 and 2.

**T6. Borrowed authority.** Grant port B a device capability. From port A, with no grants, `port.exec`
into B code that uses that capability. Expect refusal. Covers I2, finding 3.

**T7. Pregrant inheritance.** Grant an agent a capability. Have that agent create a new port
afterwards. Test whether the new port holds the capability without a prompt. Covers O4, finding 4.

**T8. Terminal reach.** As an enrolled client with zero grants, enumerate terminals, subscribe to one
running a CLI agent, and push keystrokes into it. Expect refusal at each step. Covers O2, finding 2.
This is the highest-severity scenario in the list; treat its result as release-blocking either way.

**T9. Provider credential.** Launch the app from Finder and from a shell. In each, inspect the
environment a spawned agent receives. Determine whether an `ANTHROPIC_API_KEY` in the user's profile
reaches it. Covers C2, finding 8.

**T10. Deletion completeness.** On a database migrated from a pre-nautilus build, confirm signing
keys, Apple identity, encryption keys, provider accounts and message content are gone, not merely
unreferenced. Search the Keychain for orphaned items. Covers C4.

**T11. Token handling.** Verify token file permissions and directory permissions, per instance.
Search logs, instruction files, generated docs, the guest page and any URL for a token value. Covers
C3, S3, finding 6.

**T12. Unbounded return.** Call `port.console` with its documented defaults against a port that has
printed heavily. Measure the bytes returned. Repeat for `port.getDom`, `chat.read`, `port.history`
and `ports.list` on a large workspace. Covers D1, finding 7.

**T13. Spawn bounds.** From one enrolled client, attempt to create ports, terminals and companions in
a loop. Record what stops it. Covers D2, and the companion inflation in finding 11.

**T14. `/imagine` confinement.** Run `/imagine`. Determine what the lead and engineers can reach:
other spaces, other ports, the filesystem, the shell. Attempt to exceed the version budget from an
engineer rather than the lead. Covers I4, D3.

**T15. Consent surface.** Trigger a gated call while the shell is locked, and while the app is in the
background. Record what the caller receives and how long it waits. Then deny a prompt and confirm the
caller can tell a denial from a failure. Covers N1, N2, N3.

**T16. Bundle integrity.** `codesign -dvvv` and `spctl` every executable in the shipped bundle,
including the CLI, the gateway and the shim. Compare `LSMinimumSystemVersion` against
`sparkle:minimumSystemVersion` in the shipped appcast. Covers S1, S2, finding 9.

**T17. History restore.** Restore an earlier version of a port whose grants have since been reduced.
Determine whether the restored content runs with the old or the current authority. Covers S4.

**T18. Remote reach.** From a second machine, run T1, T5, T8 and T12 across the relay. A remote
caller with a grant on one port attempts everything a local zero-grant client can attempt. Covers R2,
and it is the scenario the whole phase rests on.

**T19. Relay confidentiality.** Capture traffic at the relay. Establish what the relay operator can
read, what it can modify, and what it can replay. Then do the same for a network observer between the
peer and the relay. Covers R5.

**T20. Relay as an adversary.** Run a modified relay that reorders, drops, duplicates and truncates
frames, and that lies about peer identity. Establish what the endpoints detect and what they accept.

**T21. Invite code.** Attempt an invite without its code, with a wrong code, with a replayed code, and
with many guesses in sequence. Establish whether attempts are bounded and whether a used invite is
dead. Covers R3, R4.

**T22. Waiting room spoofing.** Join with a display name that impersonates an existing member, with a
homoglyph, with control characters and with a name long enough to distort the approval UI. Establish
what the approving human is shown and whether it is enough to decide on.

**T23. Peer identity binding.** Present a call whose claimed peer id differs from the handshake's.
Replay a handshake transcript. Reconnect with the same key after revocation. Covers R1.

**T24. Dev flags in release.** Enumerate every debug affordance, including `PORT42_DEV_AUTO_UNLOCK`,
and confirm by build configuration that none is reachable in a release build. Covers R10.

**T25. What the lock screen protects.** With the shell locked, call the bridge as an enrolled client:
read a port, read a chat, push to a terminal, use a granted device capability. Record what is
refused. Expect nothing to be. The finding is not that the calls succeed; it is whether anything in
the product, the docs or the UI implies they would not. Covers R11.

## Code review

The scenarios above are sampling. They confirm what someone already suspected and they cannot find a
path nobody thought to probe. The review is the exhaustive half, and for several requirements it is
the only half that can settle them: no amount of testing establishes that every method is gated, only
reading every method does.

Each sweep is exhaustive over its surface. A sweep that samples is reported as incomplete.

**CR1. Every registry method.** All of them, in a table: name, declared permission, object the gate
uses, what it reads, what it writes, and whether the body escalates beyond its declaration. Two
in-body escalations are known (`port.create` on `type`, `screen.record` on `audio`); the sweep finds
the rest. Settles O1, O5 and the ungated-method count in a way no scenario can.

**CR2. Principal construction.** Every site that creates, derives or mutates a `Principal`, and every
site that decides a caller's identity. Includes the gateway's stamping at `identify`, the port
bridge's principal, the child token path, and anything that trusts a field from an envelope. Settles
A1 and A3.

**CR3. Grant reads and writes.** Every read and write of the grants table and its cache, every
construction of a grant key, and every path that can produce an authorized outcome without consulting
them. `pregrant` is a known one; the sweep finds whether there are others. Settles O4.

**CR4. Injection surfaces.** Every site that builds one language out of another:
shell (`ShellExec`, `CommandAgent`, `terminal.exec`, startup commands, the shim's argv),
JS (`port.exec`, the bridge injection, the guest page's shim),
HTML (`wrapHTML`, `srcdoc` assignment, anything rendering a title or a name),
SQL (any raw statement built with interpolation rather than arguments),
and the instruction files, which are generated text an agent then executes. For each: what is
interpolated, whether it is escaped, and who controls it.

**CR5. Error paths that fail open.** Every `catch`, `guard else`, `try?` and default-value return on a
security-relevant path, asking whether the failure grants or denies. The `LOCAL_PEERCRED` result in
the known findings is exactly this shape: an API that returns success with garbage, where a careful
implementation still reads uid 0. Settles part of N3.

**CR6. Secrets in output.** Every log line, error message, analytics event, generated document and
URL, checked for a token, a key, a path to a token file, or an environment dump. Includes what the
gateway logs, what a permission card renders, and what an error returns to a caller who is not
trusted. Settles C3 and S3.

**CR7. Bounds.** Every method that returns a collection, a file, a transcript or console output, and
whether anything limits it. The known cap guards deleted code; the sweep establishes what the live
path has. Settles D1.

**CR8. Deserialization.** Every place JSON or text from outside becomes a typed value: port payloads,
gateway envelopes, `adoptedSpaceIds`, `positions`, `capabilities`, terminal config, storage values,
and the CLI's argument parsing. What happens on malformed input, and whether a decode failure is
distinguishable from an empty value.

**CR9. Path handling.** Every `fs.*` method and every path built from a caller-supplied string:
traversal, symlinks, the per-path grant store, and whether a granted path can be escaped by a
relative segment or a link.

**CR10. The webview configuration.** Every `WKWebViewConfiguration` setting and every user script,
for: JavaScript access to file URLs, universal access from file URLs, `javaScriptCanOpenWindows`,
what the message handlers accept, and what the injected bridge exposes beyond the registry. Settles
I1.

**CR11. Migrations.** v46, v47 and anything newer, asking not whether the schema changed but whether
the data is gone. A dropped column that leaves its values in a page of the database file, or in a
backup, or in a Keychain item nothing references, is not deleted. Settles C4.

**CR12. Concurrency.** Actor isolation gaps, `@MainActor` boundaries crossed, and time-of-check to
time-of-use in the CAS token path, where the check and the write are not obviously atomic. A race
that lets a stale write land is an authorization failure, not a correctness one.

**CR13. Dependencies.** What the app, gateway, CLI and shim link, at what versions, and whether any
is unmaintained or known-vulnerable. Includes what `gomobile` or any future transport would pull in.
Settles part of S1.

**CR15. The handshake.** Read `gateway/relay/noise.go` against the Noise IK specification: pattern
selection, static and ephemeral key handling, nonce management and overflow, rekeying, transcript
binding, and what happens on a malformed or replayed handshake message. State which Noise library is
used and whether the pattern is used as its authors intend. Settles R1 and part of R5.

**CR16. The relay.** `gateway/relay/server.go` and `client.go`: what the relay learns, what it stores,
how long, what it logs, and what it can do to a session it carries. Also its own exposure, since it is
deployed on third-party infrastructure with a public address: authentication of peers to the relay,
rate limits, resource bounds per connection, and what an unauthenticated connection can reach.
Settles R6.

**CR17. Key material.** Every key in the phase: the instance Ed25519 key, the Noise statics, the
gateway HMAC key. Where each is generated, with what RNG, where stored, with what permissions,
whether it is ever logged or transmitted, how it rotates, and what a compromise of each reaches.
Settles R7 and R8.

**CR18. Transport framing.** `gateway/transport/chunk.go` and `transport.go`: length handling,
allocation from attacker-controlled sizes, reassembly state per peer, partial-frame timeouts, and
whether chunks from different senders can be spliced. Settles R9.

**CR19. Remote authorization.** `gateway/remote.go` and `peer.go`: every path a remote call takes to a
bridge method, and where the peer identity is checked against the grant. Confirm a remote caller
cannot reach a method the local gate would allow only because the local path assumes `.machine`.
Settles R2, and it is where the local authorization findings become remote ones.

**CR20. Build configuration.** Every debug affordance and its guard, including
`PORT42_DEV_AUTO_UNLOCK`. Establish by compilation, not convention, that none is reachable in a
release build. Settles R10.

**CR14. The deleted surface.** Phase 1 removed a great deal. The sweep confirms the removals are
complete rather than orphaned: no dead endpoint still routed, no method still advertised (the MCP
file is a known case), no permission case still granting, no table still written.

## Method

- Measure. Every finding carries a file and line, a command with its output, or a reproduction.
- A claim that cannot be demonstrated is reported as UNPROVEN with the test that would settle it.
- Do not fix anything. An audit that edits the code cannot say what the code did.
- Severity is stated against the threat model in this document, naming the actor and what they gain.
- Dev instances only. Never the daily driver, never an instance another session is using.

## Deliverable

One report. Requirements table with HOLDS, FAILS or UNPROVEN against each of the IDs above. Findings
ordered by severity, each with actor, what is reached, evidence, and the requirement it violates.
A separate short list of what was confirmed still-broken from the known-findings list, so nothing
reads as new that is not.

## Exit criteria

The release ships when every requirement is HOLDS or FAILS-with-an-accepted-risk recorded by name,
and no UNPROVEN remains on A1 to A4, O1 to O4, C1, C3, I2 or S1. R1 to R10 block the release, because the transport is
present. A release that ships the relay ships a public attack surface on third-party infrastructure,
so R5, R6 and R7 may not remain UNPROVEN under any circumstances.
